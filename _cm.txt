新增图形界面：本地网页应用 + 独立窗口，支持粘贴图片与切换模型

需求是「不想用终端，要一个能粘贴图片、能选模型的应用」。做成
本地网页应用 + Edge --app 独立窗口。

为什么选这条路而不是原生窗口：
  1. **浏览器原生支持粘贴图片/文件**。终端做不到——实测在资源管理器里
     复制文件后剪贴板里只有 CF_HDROP、没有文本格式，Ctrl+V 什么都得不到。
  2. **不引入新依赖**。FastAPI/uvicorn 为了 MCP 服务本来就要装；
     pywebview 在 Windows 上还要拖 pythonnet，得不偿失。
  3. Edge 的 --app 模式 + 独立 --user-data-dir，开出来就是一个没有
     地址栏的独立窗口，且与日常浏览器互不干扰。WebView2 运行时本机已装。

新增：
- webui.py         FastAPI 服务：静态页、附件上传/列表/删除/回显、
                   模型列表与切换、SSE 对话流（事件会实时推送）
- butler_core.py   管家后端。把提示词、工具标签、MCP 子进程、会话与历史
                   从 email_butler.py 抽出来，**终端与网页共用**。
                   抽出来不是为了分层好看，而是避免两份实现各自漂移——
                   否则迟早出现「终端能接住『主题改成…』、网页接不住」
                   这种只在一边复现的缺陷。
- open_window.py   Edge --app 独立窗口启动器，找不到浏览器时退回默认浏览器
- static/index.html 前端（原生 HTML/CSS/JS，无构建步骤）：粘贴、拖放、
                   附件缩略图面板、模型下拉、动作卡片
- 启动应用.bat      双击启动图形界面（纯 ASCII，与既有约定一致）

顺带修一个真缺陷（由现有测试暴露）：
  上一轮加的「附件目录回退」过于宽松——**指明了目录但文件不存在时，
  它会跑到附件目录里搜同名文件**。实测把 tmp 目录里不存在的 a.txt
  判成了成功，也就是会发出附件目录里的另一份 a.txt。
  发错文件比发不出去严重得多，现收紧为：只有**裸文件名**才回落到
  附件目录；给了目录就只在该目录找。新增 2 个测试固化这条边界，
  并确认过移除修复后测试必然失败。

另修：测试曾污染真实的 attachments/ 目录（`from config import settings`
把对象绑定到各模块命名空间，只打桩 config.settings 时已绑定过的模块
仍指向旧对象）。fixture 改为逐模块打桩，并加了一个防污染断言。

会话改为流式（astream updates 模式），因此「决定调用哪个工具」
能在工具真正执行前就显示出来；ask() 与流式共用一条执行路径，
不会出现两套行为。终端版行为不变，输出仍是 ⚙/↩/⏱。

新增 62 个用例（butler_core 21 + webui 33 + open_window 6 + 边界 2）。
用例数 290 -> 352。测试：352 passed
