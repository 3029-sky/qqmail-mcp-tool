# static/ 目录的素材说明

## 随仓库分发的

| 文件 | 来源 | 说明 |
|---|---|---|
| `logo.svg` | **本项目原创** | 二次元信使机器人标识。画的是一只顶着通信天线、抱着信封、斜挎信使包、带小翅膀的萌系机器人。矢量图，任意尺寸都清晰 |
| `index.html` | 本项目 | 前端界面 |

`logo.svg` 是**兜底素材**：本机立绘加载不到时会自动退回它（见下面「降级策略」）。

## 只在本机、不进仓库的

| 文件 | 来源 | 说明 |
|---|---|---|
| `butler.png` | 用户提供的 AI 生成图（ChatGPT） | 完整立绘，512×512，用于欢迎页大图 |
| `butler-icon.png` | 同上，裁切 | 从立绘裁出脸部，256×256，用于顶栏与对话头像 |
| `butler-icon-64.png` | 同上 | 64×64，favicon |
| `butler-icon-32.png` | 同上 | 32×32，favicon |

这几个文件已被 `.gitignore` 排除。把它们挡在仓库外的原因：

**AI 生成图的著作权归属本身存在争议，无法给出一份能站得住脚的授权来源。**
对一个要用于面试讲解、并可能公开到 GitHub 的项目来说，
把来源不可证明的素材放进仓库会留下不必要的解释成本。

## 降级策略

界面里三处引用立绘的地方都带了 `onerror` 兜底：加载失败时自动改用
`logo.svg`。因此**别人克隆这个仓库后，看到的仍然是完整的原创标识**，
只是不是立绘版。这样「本地好看」与「仓库干净」两件事可以同时成立。

## 尺寸分配的原因

立绘是精细插画（原始 1254×1254）。缩到 26px 会糊成一团色块，
细节全丢。所以按尺寸分配：

| 位置 | 尺寸 | 用哪份 |
|---|---|---|
| 欢迎页 | 132px | `butler.png`（完整立绘） |
| 顶栏 | 26px | `butler-icon.png`（裁到脸） |
| 对话头像 | 30px | `butler-icon.png` |
| 浏览器标签 | 32 / 64px | `butler-icon-32/64.png` |

裁切位置是**量出来的**，不是猜的：取色统计显示 `y=22%` 处红瞳像素占
4.4%、肤色占 33%，是典型的正面头像构图；`y=10%` 那份完全没有红色，
说明眼睛被切掉了。
